**fumandocs-ui** is a Mantine adapter for Fumadocs. Import
**`fumandocs-ui/...`** directly; we implement only a **subset** of upstream
export subpaths today.

This page tracks that gap against the **pinned** upstream version used by
**create-fumandocs** (`fumadocs-core` release line), comparing **`fumadocs-ui`
(Radix)** and **`@fumadocs/base-ui`** on npm.

## What is covered

- **Classic docs sites:** `RootProvider`, `DocsLayout`, `DocsPage`, default MDX
  map, and core MDX primitives (`Callout`, `Cards`, code blocks, headings).
- **Same quickstart paths** as
  [Fumadocs layout guides](https://www.fumadocs.dev/docs/ui/layouts) for the
  default docs layout — not Flux/Glass/Notebook/Home layouts.

## What is not covered (yet)

- Alternate layouts (`layouts/flux`, `layouts/glass`, `layouts/notebook`,
  `layouts/home`, …).
- Granular **slot** modules under `layouts/docs/slots/*` and
  `layouts/docs/page/slots/*` (CLI customization targets).
- Standalone components such as `Steps`, `Tabs`, `Files`, `TypeTable`,
  `ImageZoom`, and separate search dialog entrypoints.
- Non-Next providers (`provider/astro`, `waku`, `tanstack`, …), i18n, OG
  helpers, and legacy Radix-only paths.

<Callout type="warn" title="Ecosystem packages">
  Plugins (OpenAPI, Twoslash, etc.) often import Tailwind-specific or extra
  `fumadocs-ui` subpaths. Treat them as **unsupported** until those paths appear
  in the table below or you add local shims.
</Callout>

```bash
# Print summary + missing groups
pnpm exports:diff

# Refresh this page and write JSON for tooling
pnpm exports:diff -- --write-docs --json packages/fumandocs-ui/exports-diff.json

UPSTREAM_FUMADOCS_UI_VERSION=16.15.12 pnpm exports:diff
```

## Interpreting the numbers

Official **`fumadocs-ui`** exposes many subpaths so the CLI can install
individual layout pieces. **fumandocs-ui** intentionally publishes **fewer
entrypoints** and bundles sidebar, header, search, and TOC inside `layouts/docs`
and `layouts/docs/page`.

That means **low subpath coverage is expected**; what matters is whether
**your** imports resolve. If you copy a snippet from fumadocs.dev and get
"Module not found", check the supported list above or open an issue with the
missing path.
